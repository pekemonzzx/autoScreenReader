## 1. 代码结构

```
src/screenreader/
    config.py      集中配置（区域/设备/后端/缓存/行数上限/排队策略）
    capture.py     截屏（DXGI 主 + mss 回退 + DPI-aware + 全黑自检）
    ocr.py         OCR（RapidOCR + 线程数自动标定 + 三个性能坑的修复）
    segment.py     分句（强标点切句 -> 弱标点再切 -> 硬切 -> 碎片合并）
    cache.py       音频 LRU 缓存（磁盘持久化 + 索引 + 淘汰）
    tts/            TTS 后端抽象
        base.py       接口：synthesize / synthesize_stream
        gsv_api.py    GPT-SoVITS HTTP 后端（含流式 WAV 头解析）
    audio.py       输出设备枚举（按名字子串匹配）+ 播放（含边收边播）
    watchdog.py    显存探测与自适应分档（只降不升）
    pipeline.py    主编排：截屏->OCR->分句->合成流水线->播放
    cli.py         命令行入口
tests/test_units.py   44 项单元测试（纯逻辑，不需要 GPU/服务/声卡）
```

设计原则：**TTS 后端可替换**。现在用 HTTP API（torch+CUDA 运行时约 3GB），
P3 导出 ONNX 后换成进程内推理（约 700MB，DirectML 支持任意显卡），上层流水线不用改。

## 3. 流水线行为（含三条实测教训）

```
截屏 ─► OCR ─► 行级去重 ─► 分句 ─► [合成队列] ─► 逐句合成/播放
                  │                    │
          只取相对上轮新增的行    积压时优先丢已滚出屏幕的
```

### 教训 1：不要"一有新内容就打断"

最初每次新读屏都打断上一轮。实测 **44 次读屏只合成出 2 句**——第一句还在播，
下一轮就把它掐了，永远读不到第二句。

改法：`interrupt_on_new=False`（默认），改成**排队**。让合成追上文字出现的速度即可。

### 教训 2：必须做行级去重

屏幕通常只有一行在变（弹幕滚动 / 数值跳动）。不做去重的话，每轮都把整块 13~14 句
重新排一遍——靠缓存虽然不慢，但听起来是把同一段话反复念。

改法：只朗读相对上一轮**新增**的行。OCR 对同一行两次识别结果可能有细微差异
（实测出现过 `deepseek` / `dleepseek` / `dleepseekHARNESS`），所以用
「去标点+小写」归一化 + `difflib` 相似度 ≥0.85 判重，不能直接字符串相等。

变化行占比 ≥60% 时判定为整屏刷新，全部朗读（切场景时避免只念出零散几行）。

### 教训 3：积压淘汰要优先丢"已滚出屏幕"的

队列截断时如果直接丢最旧的，那句会被标记成"见过"，后续轮次不再重排，
于是**永久不会被朗读**。第一次跑就丢了 10 句（13 句只念了 3 句）。

改法：淘汰时优先丢**当前屏幕已不存在**的内容；还在屏幕上的留着念完。
`max_backlog` 必须明显大于"一轮能切出的句数"，否则一轮之内就被自己截断（默认 8）。

## 4. 实测数据

### 4.1 TTS 显存占用（RTX 4080 SUPER，v2ProPlus fp16）

| 项 | 实测 |
| :--- | :--- |
| 模型加载后常驻 | **2007 MB** |
| 单次推理峰值增量 | **789 MB** |
| **总计** | **≈ 2796 MB** |

OCR 走 CPU，显存占用 0。所以判据是"**游戏跑起来之后的空闲显存能不能再放下 2.8GB**"。

自适应档位（`reserve_mb` 语义是"给游戏/OBS 继续增长的安全余量"，默认 768MB，
**不是**游戏已占用总量——把两者叠加会把游戏算两遍，这是之前阈值定错的根因）：

| 档 | 空闲显存 | sample_steps | 合成线程 | 行数上限 |
| :--- | :--- | :--- | :--- | :--- |
| A | ≥ 4.0 GB | 32 | 2 | 25 |
| B | 3.1–4.0 GB | 16 | 1 | 20 |
| C | 2.2–3.1 GB | 8 | 1 | 12 |
| D | < 2.2 GB | 8 | 1 | 8 |

看门狗每 10 秒复查，**只降不升**（避免抖动）。

### 4.2 端到端表现

| 环节 | 实测 |
| :--- | :--- |
| 截屏（DXGI） | 0–2 ms |
| OCR（760×300，约 19 行） | 200–230 ms |
| 分句 | < 1 ms |
| TTS 流式首包 | **379–670 ms** |
| TTS 非流式 | 567–1830 ms（随文本长度） |
| **缓存命中** | **0 ms** |
| 缓存命中率（重复屏幕内容） | **70–94%** |

**首句出声 ≈ 截屏 2ms + OCR 220ms + 首包 400ms ≈ 0.6 秒**（不含播放设备缓冲）。

显示器枚举 / 音频设备 / 显存探测 / TTS 探活 / 抓帧 / OCR / 分句 / 缓存读写 / 流式合成
