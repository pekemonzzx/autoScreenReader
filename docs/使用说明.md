# 读屏台使用说明（交互式模式）

> 这是与「自动循环朗读」并列的另一种模式，也是**真实使用场景**：
> 框选区域 → 持续识别 → 按句列成卡片 → **手动点播** → 屏幕上的字消失了就自动销毁。

## 2. 操作流程

```
① 点工具栏「框选区域」
       └─ 屏幕变暗，按住左键拖出矩形，松手即确定一块
       └─ 可连续框多个（会编号 1、2、3…并按顺序配色）
       └─ Backspace 撤销上一个 / 右键撤销 / Enter 完成 / Esc 取消

② 点「开始识别」
       └─ 每 0.5 秒轮询一次所有勾选的区域

③ 识别到的文字按行变成卡片
       └─ 每张：[区域色条] [▶/⏹] 文本 [状态]
       └─ **行首只有一个按钮**，按状态自动换图标：
              ▶ 可播（未合成好也能点，合成完自动播）
              ⏹ 正在播，点了停
              ↻ 合成失败，点了重试
       └─ 状态文字：合成中… / 就绪 / 就绪·缓存 / 播放中 / 失败

④ 点行首按钮播放/停止
       └─ 同一时刻只播一句（点另一句会打断当前这句）

⑤ 屏幕上的文字消失后，对应卡片/语音/按钮**自动销毁**
       └─ 连续 3 轮（约 1.5 秒）看不到才销毁——OCR 会漏帧，不能一帧没了就删
```

### 工具栏

| 按钮 | 作用 |
| :--- | :--- |
| 框选区域 | 打开全屏框选层 |
| 删除所选区域 | 删掉左侧选中的区域（连带销毁它的卡片） |
| **显示区域角标** | 在屏幕上常驻画出各区域的**四角角标 + 序号 + 名称**，随时看得见边界；默认开，可勾掉隐藏 |
| 开始识别 / 停止识别 | 启停轮询 |
| 全部停止 | 立即停止当前播放 |
| 清空卡片 | 清掉所有卡片 |
| 显示悬浮条 | 切换**悬浮字幕条**模式（无边框、置顶、半透明，可拖动） |

左侧区域列表的**勾选框**控制该区域是否参与识别；点某个区域可以只看它的卡片。

### 识别模式：单行 / 整段

**每个区域可以单独设置**，用左侧区域列表下方的「识别模式」下拉框切换
（先在上面选中一个区域，下拉框才会生效）。

| 模式 | 行为 | 适合 |
| :--- | :--- | :--- |
| **单行**（默认） | 每个 OCR 行 = 一句话 = 一张卡片，识别后**手动点播放** | 聊天弹幕、字幕条、逐条消息 |
| **整段** | 把折行的多行**合并回句子**，按标点分句；**稳定后手动点按钮**从上到下顺序朗读 | 小说正文、长文、大段说明文字 |

#### 整段要解决的痛点

OCR 是按**视觉行**返回的。一段话在屏幕上折成几行时，每行都是"半截话"，
逐行送去合成听起来就是一句一顿、语义破碎。

整段模式按这个规则还原：

```
行尾没有句末标点  ->  是自动折行，和下一行合并
行尾是 。！？；…  ->  真正的句子边界，切开
行尾是 ，、：      ->  同一句的中间，合并
```

例（屏幕折成 5 行）：

```
他那个写了很多规则，
主要是为了让玩家不要乱想。
还有啊，我觉得这个本子
写得挺有意思的，
值得再玩一次。
```

整段模式切出 **2 句**：

```
1. 他那个写了很多规则，主要是为了让玩家不要乱想。
2. 还有啊，我觉得这个本子写得挺有意思的，值得再玩一次。
```

#### 播放方式：**手动点，不自动播**

滚动/翻页时区域内容每 0.4 秒就变一次。如果每次都建卡合成，会不停播报
"刚出现的前几个字"，等页面停下来想完整读时，卡片已经被这些碎片搅乱、顺序也乱了。

所以整段模式是**两段式**：

1. **内容稳定 0.75 秒**才建卡、才送去合成 —— 滚动中一张卡都不建
2. 稳定后，**用户点左侧的「▶ 朗读这个区域（整段）」**，从上到下顺序读

播放时：

- **严格按屏幕上从上到下的顺序**（内部按 `seq` 创建序号排）
- **前一句没播完不会跳去播后面的**；某句还在合成时会原地等它
- 句子之间有 0.35 秒的自然停顿
- 某句合成失败就跳过，不会把整段卡死
- 内容一变，正在读的旧段落**立刻作废**，队列清空

> 为什么不等"合成完再一起播"：并行合成下第一句通常很快就好了，
> 点播放立刻就能出声，不用等整段。

#### 其它细节

- **中英之间自动补空格**：`GPT-SoVITS` + `做的` → `GPT-SoVITS 做的`
- **英文句号不会误切**：`3.5 元`、`www.a.com` 不会被当成两句
- **超长句会在逗号处再切**，避免 TTS 断气
- 切换模式会**清掉该区域的旧卡片**（单行的碎句和整段的合并句语义不同，不能混在一起）

**区域设置会存进 `data/config.json`**，重启后自动恢复，不用每次重新框选。

### 区域角标

框选完之后，屏幕上会常驻显示每个区域的**四个角**（L 形）+ 序号徽标 + 区域名，
中间完全透明，**点击穿透**（`WindowTransparentForInput`），不会挡住游戏或聊天窗口。
停用的区域角标会变淡并标注"（已停用）"。

### 两种显示模式

- **独立窗口**：默认，卡片列表 + 每句播放按钮，看得清楚
- **悬浮字幕条**：贴在最上面，只显示文本 + 行首按钮，尽量不挡游戏画面；拖动顶部标题区移动

两者共用同一套卡片逻辑，**状态同步刷新**，切换只是换个显示位置。

## 3. 配置文件 `data/config.json`

```jsonc
{
  "capture": { "region": null },          // 界面里框选，这里一般不用改
  "ocr": {
    "max_lines": 25,                      // 每个区域最多读多少行
    "min_score": 0.5,                     // 置信度下限，调高可滤掉误识别
    "det_limit_side_len": 960
  },
  "tts": {
    "ref_audio": "...wav",                // ★ 必填，参考音频（音色来源）
    "prompt_text": "今天播好早，…",         // ★ 参考音频对应的文字
    "sample_steps": 32,                   // 显存紧张时会被自动降到 16/8
    "speed_factor": 1.0
  },
  "audio": { "device": "" },              // 直播填 "CABLE Input"
  "cache": { "enabled": true, "max_entries": 500, "max_mb": 512 },
  "pipeline": { "min_interval_s": 0.5 }   // 轮询间隔
}
```

卡片生灭规则也可以调（`BoardConfig`，见 `src/screenreader/board.py`）：
`destroy_after_misses`（连续漏几轮算消失）、`match_threshold`（多相似算同一句）、
`granularity`（`line`=每行一张卡 / `sentence`=行内再按标点切句）。

## 4. 架构（改代码前先看这里）

```
board.py      区域/卡片数据模型 + 生灭规则     ← 纯逻辑，不依赖 Qt，可单测
worker.py     轮询识别 + 后台预合成 + 单实例播放  ← 只用 threading，不依赖 Qt
segment.py    分句 + 送 TTS 前的文字清洗
ui/           只是把上面两层画出来、把操作转回去
    region_picker.py   全屏拖拽框选
    region_overlay.py  区域角标（点击穿透）
    cards.py           卡片行 / 卡片列表
    main_window.py     主窗口 + 悬浮条 + 事件桥
    app.py             入口与主题
```

**关键约束 1**：`worker.py` 的回调来自工作线程，**绝不能直接碰 Qt 控件**。
`main_window.py` 里的 `EngineBridge` 把回调转成 Qt 信号，Qt 自动走队列连接投递到主线程。

**关键约束 2**：有三个视图共享同一份卡片状态——`card_list`、`overlay.cards`、`region_overlay`。
卡片事件必须**全部同步刷新**。`MainWindow.views` 就是为此存在的属性；
**新增视图时一定要挂进 `views`**，否则会出现"悬浮窗没内容"这类问题
（这正是第一版悬浮条为空的原因：只刷了主列表）。

### 五条必须记住的实测教训

| # | 教训 | 现状 |
| :--- | :--- | :--- |
| 1 | **"一有新内容就打断"是错的**。自动模式里实测 44 次读屏只合成出 2 句——第一句还在播就被下一轮掐了 | 交互模式本来就不自动播，问题不存在；自动模式已改成排队 |
| 2 | **OCR 会抖**。同一行两次识别可能给出 `deepseek` / `dleepseek` / `dleepseekHARNESS`。直接比字符串会误判成新句、反复建卡片 | 用「去标点+小写」归一化 + `difflib` 相似度 ≥0.85 判重 |
| 3 | **OCR 会漏帧**。游戏画面、遮挡、动画都会让某行某一帧识别不到 | 连续漏 `destroy_after_misses`（默认 3）轮才销毁 |
| 4 | **送去合成前必须清洗文字**（见下） | `segment.clean_for_tts` |
| 5 | **`prompt_text` 必须和 `ref_audio` 对得上**（见下）——**最容易踩、症状最怪** | 已修正；用 `tools/probe_audio.py --asr` 自查 |

另外：相似度在 0.85~0.92 之间时视为"同一句但内容变了"，会更新文字并**重新合成**；
≥0.92 只更新文字、**沿用已有语音**（避免 OCR 抖动导致白合成）。

#### 教训 4 详情：行首编号会被念成怪音

**现象**：用户框选聊天窗口后，点播放会说出一段听不懂的怪音，然后才是正文。

**原因**：聊天列表的行首带编号，OCR 出来是 `1语音输出前有奇怪的东西`。
GPT-SoVITS 会把那个孤立的 `1` 念成一个单独的音——听起来就是"语音前面多了个奇怪的东西"。

**处理**（`segment.clean_for_tts`，在建卡片之前做，所以界面显示的文字 == 实际会念的文字）：

| 处理 | 例子 |
| :--- | :--- |
| 去掉行首列表编号 | `1语音输出前…` → `语音输出前…`、`2. 开始识别后` → `开始识别后` |
| **但保留数量词前的数字** | `3分钟` 保持 `3分钟`（不能被削成 `分钟`）、`2024年` 保持 |
| 去掉带圈数字/项目符号/箭头 | `④ 新会话` → `新会话`、`• 第一项` → `第一项`、`>. 运行命令` → `运行命令` |

#### 教训 5 详情：`prompt_text` 必须和 `ref_audio` 对得上（最常见的坑）

**现象**：每句话开头都多出一段听不懂的内容。

**原因**：GPT-SoVITS 把 `ref_audio` 当成"已经说了一半的上下文"，用 `prompt_text` 对齐。
两者不一致时，模型会把错位的内容**续写到输出前面**。

**实测证据**（本项目真实踩到的）：

```
参考音频 ..._0002067200_0002231040.wav 的 ASR 转写：
    一直在调那个进度条，就是没看到打架。
当时配置的 prompt_text：
    今天播好早，哎呀呀呀，醒了醒了早点播，早点播。   ← 这是另一个切片的文本

合成 "我的项目" 后用 ASR 转回来：
    洗呀洗呀，早点播 我的项目。      ← 前面多出来的就是错位的 prompt 内容
```

修正 `prompt_text` 之后，同样的测试：

```
我的项目   -> 我的项目。
工作区     -> 工作贴。          （ASR 把"区"听错，但没有多余前缀）
```

**怎么自查**：用 `tools/probe_audio.py --asr` 会打印一条 PowerShell 命令，
执行它就能看到参考音频到底说了什么：

```powershell
$env:PYTHONPATH='src'
.\.venv\Scripts\python.exe tools\probe_audio.py --text "我的项目" --asr
# 然后按提示把命令贴到 PowerShell 里跑
```

**注意**：不要指望在这个工具内部直接跑 ASR —— 本进程跑在受限环境里，
它再 spawn 一个需要读写 `D:\GPT-SoVITS` 的子进程会**一直挂住**；
从 PowerShell 直接跑同样的命令只要 ~33 秒。
| 丢掉不值得念的行 | 纯符号、纯数字、单字（`has_speakable`） |

## 5. 无界面排障工具

界面出问题时先用它定位（也是目标机上排查的手段）：

```powershell
$env:PYTHONPATH='src'
.\.venv\Scripts\python.exe tools\board_demo.py --region 0,0,760,300 --duration 30
.\.venv\Scripts\python.exe tools\board_demo.py --region "0,0,700,200" --region "0,760,700,240"
```

它会实时打印每张卡片的 `＋新句 / ✓合成好 / －消失`，最后给出统计。
判断标准：**"链路正常 ✅"** 表示识别和合成都通了。

常见问题：

| 现象 | 原因 |
| :--- | :--- |
| 全是 `✗ 合成失败`，HTTP 400 | `tts.ref_audio` 为空，或参考音频路径不存在 |
| `＋新句` 一堆乱码短词（"品""日""x"） | 区域选到了图标/工具栏。**换一块有连续文字的区域** |
| 一句都识别不到 | 区域坐标不对（多屏时注意坐标是相对该显示器的） |
| `抓帧失败` | 远程桌面 / 虚拟显示器接管了屏幕 |

## 6. 已知限制

| 限制 | 说明 |
| :--- | :--- |
| 合成吞吐跟不上时老卡片会停在"合成中" | 一次冒出 20+ 句时，合成速度约 2.5 秒/句。滚走的卡片会被跳过（不浪费 GPU），但留下来的要排队 |
| 播放设备未在真机验证 | 本机没有 VB-CABLE，只验证到"默认设备出声" |
| 框选只在主屏测试过 | 多屏代码走的是虚拟桌面并集 + 按显示器拆坐标，逻辑对但没实机跑过 |
| 无快捷键 | 播放/停止只能点按钮；全局热键未做 |
| 界面启动后不能再改区域坐标 | 只能删掉重框 |
