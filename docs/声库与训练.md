# 声库与训练（换音色 / 换语料怎么做）

> 目标：**训练、训练配置、推理配置全部独立可替换**。
> 换一个人重训、或者直接用别人的模型，都只是换一个目录、改一个名字的事。

---

## 1. 声库档案是什么

一个音色的所有东西打包在一个目录里：

```
voices/
  voice01/                    ← 一个声库就是一个目录
    voice.json                元数据 + 推理配置（权重路径 / 参考音频 / prompt_text）
    train.yaml                训练配置（版本、预训练模型、batch/epoch…）
    ref.wav                   参考音频（推理时用来克隆音色）
    train.list                训练标注（wav路径|说话人|语言|文本）
    tts_infer.yaml            自动生成，给 api_v2.py 用
    README.md                 来源说明与注意事项
```

**为什么把 `ref.wav` 和 `prompt_text` 放在一起**：这两者**必须对得上**，
否则模型会把错位内容续写到每句话开头（听起来像听不懂的怪音）。
本项目实际踩过这个坑，详见 [使用说明.md](使用说明.md) 教训 5。
放在同一个档案里 + `voice verify` 自检，就不容易再犯。

## 2. 常用命令

```powershell
$env:PYTHONPATH='src'

# 看看有哪些声库、当前用哪个
python -m screenreader voice list

# 看某个声库的全部细节（含启动推理服务的命令）
python -m screenreader voice show voice01

# 切换到某个声库
python -m screenreader voice use voice01

# 自检（文件是否齐、权重是否存在、参考音频时长、prompt 一致性提示）
python -m screenreader voice verify voice01
```

## 3. 训一个新音色

### 3.1 准备语料

先用整合包自带的 WebUI 做切片和自动标注（本项目用的流程）：

```powershell
# 启动音频标注 WebUI（Gradio 要放开目录白名单，否则 Submit Text 会 403）
scripts\start_subfix.bat
```

标注完导出 `.list`，用 `tools/filter_list.py` 做机械过滤（去太短/纯符号/重复）。

### 3.2 建声库档案

```powershell
python -m screenreader voice new myvoice `
    --display "我的新音色" `
    --version v2ProPlus `
    --list "D:\语料\myvoice.list" `
    --wav-dir "D:\语料\slices" `
    --source "语料来源说明"
```

`--list` 会被**复制进档案**（这是你以后要编辑的东西）；`--wav-dir` 保持外部引用
（切片通常几十 MB，没必要复制）。

> **版本只能选 v1 / v2 / v2Pro / v2ProPlus**，而且新版整合包只支持 v2Pro / v2ProPlus。
> 训练和打包都建议 **v2ProPlus**（只有 v2 系列有 ONNX 推理路径）。

### 3.3 挑参考音频

```powershell
# 自动从训练集里挑一条 3~6 秒、汉字占比高、够长的
python -m screenreader voice pick-ref myvoice --min-sec 3 --max-sec 6

# 或者手动指定（--text 必须写音频里实际说的话！）
python -m screenreader voice set-ref myvoice --wav D:\some\slice.wav --text "这句话是音频里说的"
```

### 3.4 训练

```powershell
python -m screenreader voice train myvoice `
    --s2-batch 6 --s2-epoch 8 `
    --s1-batch 8 --s1-epoch 15
```

训练参数也可以在 `voices/myvoice/train.yaml` 里改（**命令行优先级更高**）：

```yaml
version: v2ProPlus
gsv_root: D:\GPT-SoVITS\GPT-SoVITS-v2pro-20250604
list_path: train.list
wav_dir: D:\语料\slices
s2_batch: 6          # SoVITS 批大小，显存不够就调小
s2_epoch: 8
s1_batch: 8          # GPT 批大小
s1_epoch: 15
save_every: 4
fp16: true
```

分步重跑（改完某一阶段不用全跑）：

```powershell
python -m screenreader voice train myvoice --skip-1abc   # 只重训 SoVITS + GPT
python -m screenreader voice train myvoice --skip-1abc --skip-s2   # 只重训 GPT
```

### 3.5 刷新权重并切换

```powershell
python -m screenreader voice refresh myvoice   # 自动找最新权重，重建 tts_infer.yaml
python -m screenreader voice verify  myvoice
python -m screenreader voice use     myvoice
```

界面和引擎都是**启动时**读取声库，所以要重启界面才生效。

## 4. 用别人的模型

拿到别人的 GPT-SoVITS 微调权重（一个 `.ckpt` + 一个 `.pth`）时：

```powershell
# 1. 把权重放进整合包对应目录
#    GPT_weights_v2ProPlus/<名字>-e<epoch>.ckpt
#    SoVITS_weights_v2ProPlus/<名字>_e<epoch>_s<step>.pth
#    （权重文件名的前缀必须和声库名一致，refresh 才能自动找到）

# 2. 建档案并手填路径
python -m screenreader voice new other --version v2ProPlus
# 编辑 voices/other/voice.json，填好：
#   "gpt_weights":    "GPT_weights_v2ProPlus/xxx-e12.ckpt"
#   "sovits_weights": "SoVITS_weights_v2ProPlus/xxx_e8_s248.pth"

# 3. 参考音频——必须用**对方训练时用的那条**，文本也要对得上
python -m screenreader voice set-ref other --wav 对方给的参考音频.wav --text "音频里实际说的话"

# 4. 刷新 + 自检 + 切换
python -m screenreader voice refresh other
python -m screenreader voice verify  other
python -m screenreader voice use     other
```

> **参考音频最好管对方要**。自己从别处随手拿一条，音色会飘。

## 5. 训练实现里必须注意的六个坑

都在 `src/screenreader/trainer.py` 里处理好了，改代码时别删：

| # | 坑 | 处理 |
| :-- | :--- | :--- |
| 1 | 整合包的 `runtime/Lib/site-packages/users.pth` 硬编码了**打包者的绝对路径**，解压到别处就 `ModuleNotFoundError: No module named 'text'`；而且 PYTHONPATH 救不了（该运行时带 `python39._pth`） | `repair_users_pth()` 自动改写 |
| 2 | `prepare_datasets/*.py` 既有 `from text.cleaner`（在 `GPT_SoVITS/` 下）又有 `from tools.my_utils`（在根目录下） | 两个路径都进 PYTHONPATH |
| 3 | v2Pro/v2ProPlus 多一步 `2-get-sv.py`，缺了会 `assert os.path.exists(path7)` 失败 | 加了 `[1B-SV]` 步骤 |
| 4 | 1a/1c 的产物是**分片**的（`2-name2text-0.txt`） | `merge_parts()` 按 WebUI 的逻辑合并 |
| 5 | 实验目录必须是 `<GSV_ROOT>/logs/<exp>`，否则存 checkpoint 时目录不存在——**要跑完一轮才失败** | `exp_dir_of()` 强制该路径 |
| 6 | `python -c "<多行代码>"` 在 Windows 上会被参数解析搞坏 | 一律写脚本文件再执行 |

另外：训练必须用 **v2pro 整合包的内嵌 Python** 跑（v3lora 那个包不支持 v2ProPlus）。

## 7. 训练语料的经验

| 项 | 建议 |
| :--- | :--- |
| 时长 | 5~20 分钟足够；本项目 6.1 分钟（93 条）和 14.3 分钟（185 条）都可用 |
| 来源 | 用 UVR5 做 `HP5_only_main_vocal` 人声分离，去掉背景音乐 |
| **采样率** | **千万别低于 44.1kHz**，见下面「教训 · 采样率」 |
| 自动标注 | FunASR paraformer-large |
| **人工校对** | **务必做**。本项目 119 条里机械过滤掉 26 条，剩下的还逐条校对了一遍；校对前后音质差别明显（对比 `data/voice01_test.wav` 与 `voice01_test_v2.wav`） |
| 切片 | 3~10 秒为宜，太短克隆不稳，太长训练慢 |
| SubFix 使用 | 必须点 **Submit Text** 才落盘（否则回滚）；保存后文本会多一个尾随空格，`tts_train` 会 strip |

### 教训 · 采样率：擦音清晰度的上限由**素材**决定

**症状**：合成出来的语音大体很像，但 `ch / zh / sh / c / z / s` 这类擦音发闷、听不清。

**原因**：`tools/tts_prepare.py` 抽音轨那一步曾经写死 `-ar 16000`，
把源音频一律砍到 16kHz（奈奎斯特 8kHz）。**擦音/塞擦音的区分特征主要在 4~10kHz**，
砍到 8kHz 就只剩个"闷"的轮廓。

**实测证据**（480p 源视频，音轨本身是 48kHz AAC）：

| 频段 | 源视频里有 | 砍成 16kHz 后 | 损失 |
| :--- | ---: | ---: | ---: |
| 6–8 kHz | -29.6 dB | -34.2 dB | ~5 dB |
| **8–11 kHz** | **-36.1 dB** | **-59.0 dB** | **~23 dB** |
| **11–16 kHz** | **-40.0 dB** | **-85.0 dB** | **~45 dB** |

**信息本来就在，是管线自己扔的。**

**已修**：抽音轨默认改成 **44100 Hz**，加了 `--sample-rate` 参数，
并在代码里写明为什么不能调低。后端的 UVR5 反正会重采样到 44.1kHz，
所以保持高采样率不增加任何负担。

> ⚠️ 但**修复只能保住已有的信息，变不出没有的信息**：
> 如果素材本身就是 16kHz（文件名常带 `_16k`），那它的清晰度上限已经被锁死了，
> 重跑管线也没用——**必须换更高质量的素材**。
>
> 检查方法：`ffprobe -show_entries stream=sample_rate <素材>`

**怎么自查语料的高频**：

```powershell
$env:PYTHONPATH='src'
.\.venv\Scripts\python.exe tools\spectrum_db.py
```

正常语音在 8–11kHz 应该在 **-35 ~ -45 dB** 左右；
低于 **-55 dB** 说明高频已经没了，擦音一定会闷。

## 8. 目录与配置的关系

```
data/config.json
    └── "tts": { "voice": "voice01", ... }     ← 只写声库名
                      │
                      ▼
voices/voice01/voice.json
    ├── ref_audio / prompt_text / speed_factor  → 覆盖 config.json 里的同名字段
    └── gpt_weights / sovits_weights            → 生成 tts_infer.yaml 给 api_v2.py
```

**没写 `tts.voice` 时**，`config.json` 里的 `ref_audio` / `prompt_text` 就照旧直接生效
（向后兼容）。写了声库名就以档案为准，并在日志里提示已覆盖。
