# 打包与部署说明

> 三块分开，各管各的：
> **① 主程序**（325 MB，做安装包）· **② TTS 运行时**（9 GB，首次启动按需下载）· **③ 声库包**（~290 MB/个，独立分发）
>
> **目标机不需要 Python、不需要 CUDA 工具链。**

## 0. 为什么这么分

| | 大小 | 变更频率 | 打包方式 | 谁提供 |
| :--- | ---: | :--- | :--- | :--- |
| 主程序（界面 + OCR + 引擎） | **325 MB** | 改代码就变 | 安装包（Inno Setup） | 发布者 |
| TTS 推理运行时 | **9 GB** | 基本不变 | 首次启动**弹窗引导下载** | 发布者上传，用户下载 |
| 声库包（音色） | **~290 MB** | 换音色就变 | 独立 zip，丢进 `voices/` | 各自分发 |

好处：
- 用户拿到手的安装包只有 **325 MB**，不是 9.3 GB；
- 运行时不用跟着程序版本重新下载；
- 换音色、加音色、把音色发给别人，都只是传一个 290 MB 的 zip；
- **全程不需要 Python**——界面里点，或者用打包好的 exe 当命令行。

## 1. 发布方：准备三样东西

### 1.0 ★ 关于「未验证发布者」提示

打开程序时可能看到**两种完全不同的提示**，解决办法也不一样 —— 别混在一起：

#### 提示 A：UAC（盾牌图标，「你要允许此应用对你的设备进行更改吗？发布者：未知发布者」）

- **原因**：exe 或安装器**请求了管理员权限**。跟签不签名无关。
- **解决：不请求权限，就不会弹。** 已经改好了：

| 位置 | 改动 |
| :--- | :--- |
| 主程序 | manifest 设成 `asInvoker`，**完全不请求提权**（打包自检会检查这一项） |
| 安装器 | `PrivilegesRequired=lowest` → **按用户安装**到 `%LOCALAPPDATA%`，不弹 UAC |

> 这个程序本来就不需要管理员：TTS 运行时默认也装到用户可写的位置。
> 请求提权只会白白换来一个吓人的「未知发布者」对话框。

#### 提示 B：SmartScreen（蓝色全屏「Windows 已保护你的电脑」）

- **原因**：文件带 **Mark-of-the-Web**（从网上下载的）+ **下载信誉不足**
- **用户侧**（一次即可）：
  - 点「更多信息」→「仍要运行」
  - 或者：右键文件 → 属性 → 底部勾选「**解除锁定**」→ 确定
- **发布者侧**：**代码签名是唯一的根治办法**（见下）

#### 三条分发路线对比

| 分发方式 | UAC 提示 | SmartScreen | 成本 |
| :--- | :--- | :--- | :--- |
| **免安装 ZIP**（`--zip`） | **无** | 可能一次 | 0 |
| **按用户安装器**（默认） | **无** | 可能一次 | 0 |
| 按机器安装器（要管理员） | **有** | 可能一次 | 0 |
| 上面任意 + OV 签名 | 无（显示你的名字） | 仍需积累信誉 | ¥1000–3000/年 |
| 上面任意 + EV 签名 | 无 | **立即信任** | ¥3000–6000/年 |

> 给朋友/小范围用：**免安装 ZIP 或按用户安装器就够**，不花钱。
> 要公开发布给陌生人：再考虑签名。

#### 代码签名证书的现状（2023 年 6 月起）

- 所有代码签名证书**必须用硬件令牌或云签名服务**，**不能再是 .pfx 文件**
- 可选：
  - **Azure Trusted Signing**（微软）：约 **$9.99/月**，性价比最高；个人开发者需 3 年以上可验证历史
  - **DigiCert KeyLocker / SSL.com eSigner**：云签名，不用插 U 盘
  - **传统 USB 令牌**：证书要邮寄，签名时得插着
- ⚠️ **自签名证书没用**：依然显示「未知发布者」，SmartScreen 也照样拦。
  自签名只适合内部测试（把证书装进「受信任的根证书颁发机构」才行）
- 拿到证书后，在 `installer.iss` 里配 `SignTool` + `SignedUninstaller`，
  在 PyInstaller 的 spec 里加 `codesign_identity`（或对产物用 `signtool` 单独签）

### 1.1 主程序安装包

```powershell
$env:PYTHONPATH='src'
.\.venv\Scripts\python.exe tools\build_installer.py --inno --zip
```

做四件事：PyInstaller 打包 → 组装安装目录 → **自检** → （`--inno`）编译安装器 /（`--zip`）打免安装 ZIP。

产物：

```
build\installer_tree\          组装好的安装目录（325 MB）
  ├─ 读屏台.exe                主程序（asInvoker，不弹 UAC）
  ├─ _internal\                PyInstaller 运行时 + RapidOCR 模型
  ├─ data\config.json          配置模板
  ├─ voices\                   声库目录（空）
  ├─ gsv\                      运行时目录（空）
  ├─ start.bat                 一键启动（先起 TTS 服务再开界面）
  ├─ run_console.bat           带控制台启动（排障）
  └─ README.txt                给使用者的说明

build\installer\
  ├─ AutoScreenReader-Setup-x.y.z.exe        安装器（按用户安装，不弹 UAC）
  └─ AutoScreenReader-x.y.z-portable.zip     免安装版（141 MB，解压即用）
```

> `--skip-pyinstaller` 可以复用已经打好的 `dist\screenreader`，改配置模板时省时间。
> **自检会检查 exe 是否请求提权**，请求了就判定失败——避免又把 UAC 提示带出去。

### 1.2 TTS 运行时（两种打包方式，任选）

#### 方式 A：分卷 + 清单（推荐）

```powershell
# 先裁剪（如果还没做）
.\.venv\Scripts\python.exe tools\build_runtime.py --dest build\gsv-runtime --voice voice01 --verify

# 再分卷打包
.\.venv\Scripts\python.exe -m screenreader runtime pack `
    --src build\gsv-runtime --out D:\发布\gsv `
    --base-url "https://你的服务器/gsv"
```

产物：`runtime_manifest.json` + `gsv_part01.zip` … `gsv_part05.zip`（各 ~1.9 GB）。

**分卷而不是一个大包**：9 GB 单文件在网盘/浏览器上传里很容易出问题，而且坏了能单独重传一卷。
`sha256` 逐卷校验，下载失败会**断点续传**。

#### 方式 B：单个 zip（最省事，适合传网盘）

```powershell
.\.venv\Scripts\python.exe -m screenreader runtime pack --single `
    --src build\gsv-runtime --out D:\发布
```

产物：`gsv.zip`（~8 GB）+ `gsv.zip.sha256`。

一条直链就能装，**不需要清单**。代价是单个大文件，网盘上传容易断。

**两种方式程序都支持**，使用方在同一个界面里填就行——
地址以 `.json` 结尾就按分卷走，否则当单包处理（本地目录/zip 也一样自动判断）。

### 1.2.1 ★ 关于"传到网盘能不能自动下载"

**关键区别：程序要的是「直链」，不是「分享链接」。**

| 你手上的链接 | 实际是什么 | 程序能不能下 |
| :--- | :--- | :--- |
| `pan.baidu.com/s/1xxxx` | 一个**网页**，经常还要提取码 | ❌ 拿到的是 HTML |
| `aliyundrive.com/s/xxxx` | 网页 + 需要登录 | ❌ |
| `www.123pan.com/s/xxxx` | 网页 | ❌ |
| 对象存储 `https://bucket.oss-cn-x.aliyuncs.com/gsv.zip` | **直链**，GET 直接返回文件 | ✅ |
| GitHub Release 的 asset 链接 | **直链** | ✅ |
| 自己/别人的 HTTP 服务器上的文件 | **直链** | ✅ |

**所以有三条路：**

1. **网盘 + 手动下载**（今天就能用，最稳）
   把 `gsv.zip` 传网盘 → 使用方下载到本地 → 在安装窗口里选「**本地文件**」指向那个 zip。
   程序会自动解压、校验、配置。**不需要直链，也不需要清单。**

2. **换一个能出直链的地方托管**（真正的一键下载）
   - **对象存储**：阿里云 OSS / 腾讯云 COS / Cloudflare R2 / 七牛 —— 上传后就有直链，几块钱/月
   - **GitHub Releases**（免费，但国内下载慢）
   - **自己的服务器**，或群晖等 NAS 的 HTTP 出口
   建议用**方式 A（分卷）**：单卷断了只重传那一卷，且 sha256 能发现传输损坏。

3. **网盘直链解析服务**（有风险，不建议写进说明书）
   第三方工具能把百度网盘分享链接转成直链，但链接经常过期、限速、失效。
   临时给一两个人用可以，别依赖。

#### 程序支持的直链形式

| 形式 | 例子 | 说明 |
| :--- | :--- | :--- |
| 普通直链 | `https://host/gsv.zip` | 匿名可下 |
| **带账号密码** | `https://用户名:密码@host/path/gsv.zip` | **WebDAV、需要认证的 S3**；密码里的特殊字符要 URL 编码（`@` → `%40`） |
| S3 预签名 | `https://…?X-Amz-Signature=…` | 能用，但**会过期**，不适合长期分发 |
| 清单 | `https://host/runtime_manifest.json` | 分卷模式 |

**401/403 时程序会直接说清原因**，而不是丢一句 "Bad Request"：

```
!! 下载失败：HTTP 401 Unauthorized
   （401/403：链接需要认证或被防盗链拦了。如果是网盘分享页，请改用「本地文件」；
     如果是 WebDAV，把账号密码写进 URL：https://user:pass@host/...）
```

#### ★ 专门说 中国科技云数据胶囊（data.cstcloud.cn）

中科院旗下，实名后免费 20 GB，支持 S3 / WebDAV —— 看起来正合适。
但**能不能用取决于你走哪条路**：

| 做法 | 能不能给程序自动下载 |
| :--- | :--- |
| **网页版上传 → 分享/复制下载链接** | ❌ **不行**。它的 Web 下载直链（`https://data.cstcloud.cn/api/file/download/file/<UUID>`）做了**来源校验 + 需要登录 Cookie**，在别处请求会被当盗链拒掉（[实测记录](https://cloudflare.xingchencloud.top/p/a3bfd5db)） |
| **WebDAV 直链 + 账号密码** | ✅ **可以**。用 `https://用户名:密码@<WebDAV地址>/gsv.zip`，程序支持 Basic 认证 |
| **S3 端点 + 预签名 URL** | ⚠️ 可以，但签名会过期，不适合长期分发 |
| **alist/openlist 中转** | ⚠️ 可以，但要走你自己的服务器代理，速度受你服务器带宽限制 |

其余要点（来源：[小众软件](https://www.appinn.com/data-cstcloud-cn/)、[使用记录](https://cloudflare.xingchencloud.top/p/a3bfd5db)）：

- 免费额度 **20 GB**（未实名只有 1 GB）—— 我们运行时压缩后 ~8 GB，**够用，但占掉一半**
- 网页版上传支持**超过 4 GB** 的单文件；**用 S3 客户端（rclone / S3 Browser）则不限单文件大小**
- 速度"一般，但比免费网盘稳"

> ⚠️ **不要把未压缩的整个 `gsv` 文件夹传上去**：
> 安装器只认 **zip** 或**清单**，一个文件夹给不出"一条直链"。
> 必须先用 `runtime pack --single` 压成 `gsv.zip` 再传。

> **程序已经把这件事做得尽量宽容了**：
> - 填目录、填 zip、填清单、填任意直链，它都会自己判断该走哪条路
> - 拿到的是网页（非 zip）时会**明确报错并提示"可能是网盘分享链接"**，
>   而不是装出一个坏运行时（测试里专门覆盖了这条）
> - 下载支持**断点续传**；服务器不支持时自动改为重下（不会把文件追加坏）
> - zip 里多套了一层目录（`gsv/gsv/...`）也会自动识别并提上来

## 4. ★ 五个必须知道的坑（都实际踩过）

### 坑 1：`users.pth` 里的隐形引用 —— 最危险

集成包的 `runtime/Lib/site-packages/users.pth` **硬编码了打包者的绝对路径**。
直接复制过来，裁剪后的运行时**仍然会去原包找模块**。

后果极其隐蔽：**在本机测试完全正常，拷到目标机就崩**。
更糟的是它会把自动化验证也骗过——实测 `tools/audio_sr` 明明没复制，
服务却能正常启动，就是靠这条路径找到的原包。

**处理**：`repair_users_pth()` 在打包和安装时都重写该文件指向自己；
另有全盘扫描确认没有残留的原包绝对路径。`runtime verify` 也会检查这一项。

### 坑 2：服务能启动 ≠ 能合成

`api_v2.py` 把请求处理里的异常**吞掉**，只返回一个**空的 400 响应体**。
于是：服务正常起来、`/docs` 返回 200、权重也加载了，但每个 `/tts` 请求都 400，
日志里**看不到任何原因**。

**处理**：`--verify` 真的发一次合成请求才算通过；定位问题时绕开 HTTP 直接调
`TTS_infer_pack`，让 traceback 打出来。

### 坑 3：请求路径上才 import 的包

这些在**启动时**不用、**处理请求时**才 import，删了就掉进坑 2：

| 包 | 谁在用 |
| :--- | :--- |
| `librosa` / `numba` / `llvmlite` | `TTS_infer_pack.TTS` 第 19 行直接 import |
| `sklearn` | `librosa.decompose` |
| `matplotlib` | `AR/modules/lr_schedulers.py` |
| `wordfreq` / `mecab` / `ipadic` / `pyopenjtalk` / `eunjeon` | 语种检测的中日韩分词 |
| **`onnxruntime`** | **G2PW 中文多音字模型**（`text/g2pw/onnx_api.py`） |

所以 `SITE_DROP` 必须**保守**，只删 `gradio`、ASR 工具链、`tensorboard`、
`torchvision`、`cmake`、jupyter 这类明确无关的。

### 坑 4：`torchaudio` 看着没用，其实要

同理，`TTS_infer_pack` 会 import 它。

### 坑 5：windowed 程序崩溃必须留痕

PyInstaller 用 `console=False` 打包时，启动失败**可能什么都不显示**——
双击没反应，用户完全无从下手。

**处理**：`packaging/entry_gui.py` 把 traceback 写进 `data\crash.log`，
同时弹一个消息框；正常日志写 `data\screenreader.log`。

> 附带一提：用 `Start-Process` 检测这类 GUI 程序的存活会**挂住**，
> 得用 .NET `Process` 抓 stdout/stderr 才看得到真实情况。我因此差点误判 exe 是坏的。

### 坑 6：目标机没有 Python

原本的安装说明写着 `python -m screenreader runtime install ...` ——
**目标机上根本执行不了**。所有面向使用者的提示都必须区分运行环境：

```python
def cmd_prefix() -> str:
    if getattr(sys, "frozen", False):        # 打包后
        return f'"{Path(sys.executable).name}" --runtime'
    return "python -m screenreader runtime"  # 开发期
```

同时 exe 要能**当命令行用**（`读屏台.exe --runtime status`），
而且因为是 windowed 模式看不到控制台，输出要同时写进 `data\cli_output.txt`。

### 坑 7：`.bat` 里绝不能出现非 ASCII 字符

**实际事故**：写 `start.bat` 时用了 `encoding="ascii", errors="replace"`，
把 `读屏台.exe` 里的中文**静默替换**成了 `?`，用户双击直接报：

```
Windows 找不到文件 'D:\...\installer_tree\???.exe'
```

而且 `chcp 65001` 也救不了——cmd 读取 .bat 用的是 OEM 代码页，
中文在 .bat 里本来就不安全（GBK 的尾字节会和 `&` `|` `>` 打架）。

**处理（两层）**：

1. **启动脚本纯 ASCII，用通配符定位 exe**，不硬编码任何文件名：

```bat
set "APP="
for %%f in ("%HERE%*.exe") do set "APP=%%~ff"
if "%APP%"=="" ( echo [ERROR] No .exe found next to this script. & pause & exit /b 1 )
start "" "%APP%"
```

2. **构建时自检**（`verify_tree`）。`_ascii_bat()` 遇到非 ASCII 直接**报错**而不是替换；
组装完再检查一遍：`.bat` 是纯 ASCII、代码行里没有 `?`、
引用的 `.exe` 真实存在、`start.bat` 用了通配符。

`tests\test_packaging.py` 里有对应的回归测试，防止再犯。

## 6. 关于 P3（ONNX 导出）

**结论：优先级低，建议先不做。**

实测数据不支持"ONNX 把运行时从 3GB 压到 700MB"这个预期：

| 方案 | 运行时大小 |
| :--- | ---: |
| 整合包原样 | 17.8 GB |
| **裁剪后（已完成）** | **9.1 GB**（torch 占 4.05 GB） |
| 若 ONNX 替换 torch | ~5.0 GB |

而且：

1. **省的是磁盘，不是内存/显存**。模型该占多少显存还是多少——目标机紧张的正是
   RAM/VRAM（要同时跑游戏和直播），不是硬盘。
2. **中文前端是拦路虎**。GPT-SoVITS 文本前端依赖 `onnxruntime` + G2PW + BERT；
   LunaVox 的 `[zh]` 额外依赖 `torch`——装回来就白省了。
3. LunaVox 只支持 v2/v2ProPlus，且需要单独验证我们微调权重的转换质量。
4. 运行时现在**按需下载**，体积对"安装体验"的影响已经大幅降低。
